# 亚马逊周报 · 飞书插件

店铺 A 后端里的 `/经营周报` 插件。两个卖家账号(tangliuquan、xupeng)合并出一份汇总周报：
领星周数据 + SP-API → 周宽表与 AI 数据包 → `ai_runner`(默认模型)写周报(.md 保存) → 转成 PDF → **群里只发 PDF 周报，最后发一条概述**。

## 目录

```
plugins/
├─ 经营周报_plugin.py              # 指令、AI 调用、发文件、定时(放进店铺A的 plugins/)
└─ weekly_report/               # 数据引擎(整个目录放进店铺A的 plugins/)
   ├─ weekly_pipeline_spapi.py  # ingest(合并) / pack(AI数据包) / window
   ├─ recognize.py              # 按表头识别领星导出、统一改名、检查齐全
   ├─ render_pdf.py             # 周报 .md → 带样式 HTML → 本机 Chrome/Edge 打印成 PDF
   ├─ actions.py                # 候选动作(规则生成) + 校验 AI 选择的执行清单
   ├─ config.json               # 参数；SP-API 凭证指向 ../../ziliao/
   ├─ test/inputs/<周结束日>/    # ★ 测试数据：领星导出 + SP-API .bin(文件名随意)
   ├─ test/ raw/ spapi_cache/ weekly.db out/   # 测试工作区(自动生成)
   ├─ data/inbox/ raw/ spapi_cache/ weekly.db  # 正式工作区(自动生成)
   ├─ out/                      # 正式输出：周报_<周>.md/.html/.pdf、周宽表、数据包
   └─ logs/                     # 子进程日志
tools/local_test.py             # 本地模拟(伪造 config/feishu_gateway/ai_runner)
```

测试与正式两个工作区完全隔离(各自的数据库、SP-API 缓存、输出)。测试只用已下载的 SP-API 缓存，不请求亚马逊；
每次测试都从 `test/inputs/` 复制，原文件不动，可反复跑。

## 正式上线(领星自动化接入后)

### 领星采集插件的约定(另一个插件负责下载)
- 放到：`plugins/weekly_report/data/inbox/<周结束日>/`，周结束日=那一周的周六，例如 `data/inbox/2026-09-26/`。
- 下载完一周的全部文件后，在这个文件夹里建一个空文件 `_READY`(没有它，定时任务会认为还在下载)。
- 文件名随意(按表头识别)，但快照类文件(Listing、FBA货件、补货建议)的文件名里请带下载日期 `YYYYMMDD`，
  断货模拟从这天起算；没带日期时用文件修改日期。
- 日期范围(`/经营周报 窗口` 可查)：广告 7 张表和订单导出都选 周日~周六；Listing / FBA货件 / 补货建议 / 成本表 是快照，同一天下载。
- 所有店铺导出在一个文件里最好；如果按店铺分别下载，同类报表会自动拼接(同一店铺出现在两个文件里会报警；完全相同的重复下载自动忽略)。
- SP-API 不需要采集插件管：周报插件生成时自己拉取，缓存到 `data/spapi_cache/<店铺>_<报告>_<周结束日>.bin`。

| 报表 | 必需 | 日期 |
|---|---|---|
| Listing | 是 | 快照 |
| 推广商品报告、广告活动报告 | 是 | 周日~周六 |
| 订单导出 | 是 | 周日~周六(必须完整覆盖) |
| 广告组/广告位/关键词/自动投放/用户搜索报告 | 否(缺了广告明细和候选动作变少) | 周日~周六 |
| FBA货件、补货建议(父Asin) | 否(缺了没有断货/尺码/冗余分析，强烈建议有) | 快照，与 Listing 同一天 |
| 导出产品(含头程表) | 否(缺了没有利润/盈亏线) | 快照 |

### 运行
1. 在目标群发 `/经营周报 绑定`，再发 `/经营周报 定时 开启`：每周五 13:00(北京时间)跑上一周(周日~周六)。
   没有 `_READY` 或必需文件不全时，每 30 分钟再查一次，共 4 次；仍不行就在群里提示缺什么。
2. 手动：`/经营周报 导入 [周]`(从 `inbox/<周>/` 或 `inbox/` 导入，不要求 `_READY`) → `/经营周报 生成 [周]`。
3. 导入后文件归档到 `data/raw/<周>/`(标准文件名)，每周数据写进 `data/weekly.db`；数据包带最近 4 周，
   有上周数据时自动给环比(1b 全店本周vs上周、2b 父体本周vs上周、第十二节复盘上周执行清单)。
4. 凭证：`ziliao/亚马逊sp-api.txt`、`ziliao/亚马逊sp-api-xupeng.txt`。依赖：`pandas openpyxl requests python-amazon-sp-api markdown`；PDF 用本机 Chrome(或 Edge)，找不到时设环境变量 `CHROME_PATH`。

### 补历史周(让第一份正式周报就有环比)
按上一周的周日~周六重新下载广告与订单导出，放进 `inbox/<上周六>/` 导入并生成；快照类用当天下载的即可
(历史周的库存列会是当前值，但库存只看最新一周，环比只比销售/广告/流量)。
